AvaVideoPlayer/Playback

Use the browser backend

An Avalonia control in a .NET WebAssembly application, with browser decoding and sound.

Register before startup

using AvaVideoPlayer.Browser;

await BrowserVideoBackend.RegisterAsync();
await AppBuilder.Configure<App>().StartBrowserAppAsync("out");

The browser portion of the single AvaVideoPlayer package includes browser/avavideo.js and a transitive MSBuild target that delivers the module to the browser application. The package-only browser sample demonstrates that setup.

Compose it with other Avalonia controls

Your application and UI run in the .NET WebAssembly runtime. VideoPlayer is an Avalonia UserControl, so it can share a Grid with buttons, lists, text fields and the rest of your application. The browser backend places its HTML video/WebGL surface inside the player viewport using NativeControlHost. Playback commands cross .NET JavaScript interop; decoding and sound remain browser services.

<Grid RowDefinitions="*,Auto" ColumnDefinitions="*,260">
  <video:VideoPlayer x:Name="Player" ShowControls="False" />
  <ListBox Grid.Column="1" ItemsSource="{Binding Videos}" />
  <Button Grid.Row="1" Content="Play" Click="PlayClicked" />
</Grid>

Declare xmlns:video="clr-namespace:AvaVideoPlayer;assembly=AvaVideoPlayer" in the containing view. Call await Player.PlayAsync() from the click handler. Keep native media surfaces in their own layout region: arbitrary Avalonia overlays and transforms over a NativeControlHost have platform composition limits.

Codec support belongs to the browser

The browser backend uses HTMLMediaElement for decode and audio. MP4 H.264/AAC and WebM VP9/Opus are included in the live demo. Browser support for MOV depends on its actual video/audio codecs. H.264/AAC MOV works in the tested Chrome environment; a MOV extension alone does not guarantee playback of HEVC, ProRes or other codecs.

Sound needs a gesture

Start playback from a click or tap. Browsers can block automatic audible playback. Keep Play visible and show any playback error to the user.

Local files

The player’s file picker creates a local object URL. Files stay in the browser; the demo does not upload them. Local-file URLs are released on source replacement and disposal.

Remote 360° video

WebGL requires permission to use remote media as a texture. Serve remote video with appropriate CORS headers. Same-origin media and local object URLs avoid cross-origin texture restrictions. HTTPS, redirects and authentication must still be checked against the hosting environment.

The screening-room demo

The landing page hosts the published AvaVideoPlayer.Sample.Browser Avalonia WebAssembly application. Its player, catalog, buttons, format selectors and progress/volume sliders are composed in C# with Avalonia controls. Two unique recordings provide four selectable format variants with original sound. The separate backend test harness (AvaVideoPlayer.Demo.Browser) remains a direct JavaScript backend test harness; its 51 checks do not establish Avalonia host execution.
